# TwinCoach 設計資料一覧

**サブタイトル：PoC・本導入・API連携に向けて必要な資料整理**

作成日：2026-06-06  
対象：林さん提案・本部共有・PoC導入・hacomono API相談

---

## 結論

- TwinCoachはBtoBシステムとして扱うため、**画面が動くだけでは不十分**
- **PoC前に最低限の仕様整理**（画面・機能・権限・CSV/APIの概要）が必要
- **本導入前には権限・データ・契約・環境・運用**を正式に整理する必要がある
- **hacomono API相談前には**、連携したいデータと開発体制を説明できる状態にする必要がある

## 最初に作るべき資料 TOP5

| 順位 | 資料名 | 理由 |
|---|---|---|
| 1 | 画面一覧 | 「何が動いているか」を関係者全員が共有するための最小単位。林さん提案・本部共有の起点になる |
| 2 | 機能一覧 | 画面一覧と合わせて「TwinCoachで何ができるか」をBtoB視点で説明するために必要 |
| 3 | 権限仕様概要 | 本部/オーナー/店舗のロール設計はTwinCoachの根幹。PoC前に確認必須 |
| 4 | CSV/API連携チェックリスト | hacomono API相談前に「連携したいデータと開発体制」を整理する必要がある |
| 5 | PoC評価指標 | PoCを「なんとなく試す」ではなく「判断できる検証」にするために、開始前に指標を決める必要がある |

## 佐々木さんフィードバックの反映

| フィードバック項目 | 対応方針 |
|---|---|
| スモールスタート | 1〜2店舗のPoC先行。全店舗展開は段階導入計画で管理 |
| 設計書作成 | 本資料を起点に、STEP5以降で各資料を順次作成する |
| API相談は開発計画が固まってから | hacomono API相談前チェックリストを先に整理し、準備が整ってから相談する |
| 契約形態整理 | 請負/準委任の比較・契約論点整理を本導入前に作成する |
| 段階導入/移行計画 | 段階導入計画・移行計画として本導入前フェーズに組み込む |
| 環境整理 | 環境構成・本番/検証環境整理としてPoC開始前に作成する |
| BtoBとして進める | 全資料を「意思決定者が判断できる粒度」で作成し、開発者向けだけにしない |

## まとめ

TwinCoachは、画面デモだけで進めるのではなく、**PoC前に画面・機能・権限・CSV/API連携の概要を整理**し、**PoC開始前にCRUD・テーブル・運用ルール・切り戻しを固め**、**本導入前に契約・費用・環境・セキュリティを整理する**流れで進める。
