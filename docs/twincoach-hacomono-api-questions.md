# TwinCoach hacomono API相談用質問リスト

> STEP12 — 社内確認・相談前準備用 | 2026-06-07 作成  
> 対象：林さん・井上さん・濱口さん共有用。hacomono担当者への相談前に社内で確認する資料です。

## 結論

| 方針 | 内容 |
|---|---|
| **API相談はPoC後** | PoC前にhacomono API相談を急がない。まずCSVで小さく検証する |
| **必要性を確認してから相談** | CSVで検証したデータ項目・更新頻度・利用画面を整理してから相談する |
| **説明できる状態で相談する** | 連携目的・取得データ・環境・権限・セキュリティを説明できる状態にしてから担当者に連絡する |
| **手段として捉える** | API連携は目的ではなく、TwinCoachの運用負荷を下げるための手段 |
| **既存運用は止めない** | API連携後もhacomono/kintoneは継続稼働。TwinCoachは補助レイヤーとして位置付ける |

## 1. hacomono相談前の前提整理

相談に進む前に、以下がすべて揃っているかを確認してください。

- [ ] PoC結果がある（利用状況・現場フィードバック・改善要望）
- [ ] CSVで検証したデータ項目のリストがある
- [ ] API連携が必要な理由が明確になっている（CSV運用の課題が特定できている）
- [ ] 取得したいデータ項目が明確になっている
- [ ] データの更新頻度の要件が明確になっている（日次/リアルタイムなど）
- [ ] 取得したデータを使う画面が明確になっている
- [ ] 権限仕様概要がある（ロールごとの閲覧範囲が整理されている）
- [ ] 個人情報取り扱い方針がある
- [ ] 開発環境/検証環境の想定がある
- [ ] 本番環境の想定がある（Vercel + Supabase構成など）
- [ ] API障害時の切り戻し方針がある（CSV運用へ戻す手順など）
- [ ] APIなし運用案がある（API利用不可の場合の代替手段が決まっている）

## 4. API連携の優先度

### 最優先候補（PoC後に最初に連携を検討するデータ）

| データ | 理由 |
|---|---|
| 会員基本情報 | 全機能の基盤。CSV手動更新のコストが高い |
| 所属店舗 | 多店舗対応の正確性に直結 |
| 契約プラン | LTV/リスク計算の入力値。変更頻度が高い |
| 予約/来店履歴 | リスクスコア計算の最重要入力値 |
| 会員ステータス（継続・休会・退会）| 退会予防のトリガーに直結 |

### 次点候補（最優先が安定したら検討）

| データ | 理由 |
|---|---|
| キャンセル情報 | 離脱リスク分析の精度向上に有効 |
| 担当トレーナー | 現状は文字列管理。IDへの移行に必要 |
| 入会日/退会日/休会情報 | 継続率・LTV計算の精度向上 |
| 支払い/未払い情報 | 売上管理機能の精度向上。hacomonoを正とするか確認が先 |

### 後回し候補（本導入以降に検討）

| データ/機能 | 理由 |
|---|---|
| リアルタイム同期 | 日次同期で十分かPoC後に判断する |
| 顧客チャット連携 | 高リスク機能。本導入後に設計 |
| 精算/会計連携 | FCモデル確定後に検討 |
| 既存システム完全置き換え | hacomono/kintoneは継続稼働が前提 |

## 5. API相談時に避けるべき言い方と代替表現

| 避けるべき言い方 | 理由 | 代わりに使う表現 |
|---|---|---|
| 「何でも連携したい」 | 目的が不明確。審査・費用の増大につながる | 「PoCで必要性が確認できた項目から段階的に連携したい」 |
| 「とりあえずAPIを使いたい」 | 設計が固まっていない印象を与える | 「まずは会員/予約/来店履歴など必要最小限から確認したい」 |
| 「まだ設計はない」 | 相談が時期尚早と判断される可能性がある | 「PoC結果をもとに取得項目・頻度・画面を整理しています」 |
| 「本番データをすぐ使いたい」 | 個人情報管理の観点で懸念を持たれる | 「本番連携前に検証環境で動作確認をしてから進めたい」 |
| 「kintoneをすぐ廃止したい」 | 既存運用への影響を軽視している印象 | 「既存運用は止めず、TwinCoachを補助レイヤーとして利用したい」 |
| 「hacomonoを置き換えたい」 | hacomono側との関係に摩擦が生じる | 「権限/セキュリティを整理した上で、段階的に連携したい」 |

## まとめ

hacomono API相談は、PoCで必要性が確認できた後に行う。相談時には、取得したいデータ、利用画面、更新頻度、権限設計、開発環境、セキュリティ方針、APIなし運用案を整理し、既存運用を止めずに段階的に連携する前提で進める。
