# TwinCoach 権限仕様概要

> バージョン：2026-06-06  
> 対象：佐々木さんフィードバック反映・PoC準備・BtoB導入資料

---

## 結論

- TwinCoachは**本部・オーナー・店舗・トレーナーで閲覧範囲と操作範囲を分ける**
- **本部**は全店舗の集計・比較を見る（横断把握・戦略判断）
- **オーナー**は管轄店舗のみ見る（FC・グループ内の自管轄）
- **店舗スタッフ**は自店舗のみ見る（他店舗データは見えない）
- **トレーナー**は担当範囲を見る想定（担当会員・セッション・タスク）
- **PoCでは権限を広げず、必要最小限の閲覧範囲で検証する**
- **本導入前に詳細な権限仕様書とテストケースを作成し、権限漏れを防ぐ**

## 1. ロール定義

| ロール | 想定ユーザー | 役割 | 閲覧範囲 | 主な利用画面 | PoCでの扱い |
|---|---|---|---|---|---|
| 本部（HQ） | 本部スタッフ・経営陣 | 全店舗の横断把握・戦略判断・データ取込管理 | 全店舗（集計・比較・詳細遷移可） | ダッシュボード・LTV・店舗一覧・CSVインポート・レポート | PoC対象店舗を含む全体確認または必要範囲 |
| オーナー | FC加盟オーナー・グループ責任者 | 管轄店舗の合算管理・リスク確認・現場支援 | 管轄店舗のみ（他オーナー管轄は不可） | ダッシュボード・店舗一覧・会員・タスク・売上 | 管轄店舗のみ |
| 店舗スタッフ（store） | 店長・フロントスタッフ | 自店舗の会員対応・タスク管理・在庫・掲示板 | 自店舗のみ（他店舗は不可） | セッション入力・会員一覧・タスク・在庫・掲示板 | 自店舗のみ |
| トレーナー（trainer） | 専属トレーナー・パーソナルトレーナー | 担当会員のセッション記録・タスク・予約確認 | 担当範囲のみ（想定・将来詳細化） | 今日の予約・会員一覧・セッション入力・タスク | 担当範囲のみ（PoC中は概要確認レベル） |
| 共通（全ログインユーザー） | 上記全ロール共通 | お知らせ・設定・ログアウト | 共通機能のみ | お知らせ・設定 | 同上 |

## 2. ロール別閲覧範囲

### 本部（HQ）
- 全店舗集計（ダッシュボード）
- 店舗別比較・ランキング
- LTV・退会リスク（全店舗）
- CSVインポート（データ取込）
- 売上・未払い（全店舗）

- 在庫管理（全店舗）
- 応援掲示板（全店舗）
- レポート（全店舗）
- 各店舗詳細への遷移

### オーナー
- 管轄店舗の合算ダッシュボード
- 管轄店舗の会員一覧・詳細
- 管轄店舗のタスク一覧
- 管轄店舗の売上・未払い

- 管轄店舗の在庫・応援掲示板
- 管轄店舗詳細への遷移

- 自店舗の会員一覧・詳細
- 自店舗の介入タスク一覧
- セッション入力（自店舗会員のみ選択可）
- 自店舗の在庫管理
- 自店舗の応援掲示板

### トレーナー（trainer）
- 担当会員の一覧・詳細
- セッション入力（担当会員中心）
- 担当範囲のタスク
- 今日の予約確認

### 共通
- お知らせ
- 設定
- ログアウト

## 4. PoC時の権限方針

| 方針 | 詳細 |
|---|---|
| PoC対象店舗を限定する | 特定の1〜数店舗のみPoC参加。全店舗展開はしない |
| 本部の閲覧範囲 | PoC対象店舗を含む全体確認、または必要範囲のみに限定 |
| オーナーの閲覧範囲 | 管轄店舗のみ。他オーナー管轄店舗は見えない |
| 店舗の閲覧範囲 | 自店舗のみ。他店舗データは取得・表示しない |
| トレーナーの閲覧範囲 | 担当範囲のみ（PoC中は概要確認レベル） |
| CSVインポート | 本部のみ操作可能 |
| API連携設定 | PoC中は操作不可（設定画面は見せない or 読み取り専用） |
| 本番個人情報の取り扱い | 必要最小限のデータのみ。CSV/限定データで小さく始める |
| 不具合発生時の対応 | 既存運用（現行システム）に即時戻せる体制を維持する |

## 7. 権限まわりのリスク

| リスク | 内容 | 対策方針 |
|---|---|---|
| オーナーが他オーナー管轄店舗を見る | ロール設計の漏れにより、他FC・他オーナーのデータが見える | requireStoreAccess() でオーナースコープを厳密に検証 |
| 店舗が他店舗会員を見る | getAll() 使用時に全店舗データが返る | storeロールではgetAllForStore()を必ず使用。getStoreScopeId()で絞り込み |
| トレーナーが担当外会員を見る | 担当関係の権限制御が未整備 | 担当会員テーブルを設計し、APIレベルで絞り込む |
| CSVで不要な個人情報を取り込む | インポートデータに過剰な個人情報が含まれる | インポート前にデータ項目を確認するチェックリストを設ける |
| API連携後に取得範囲が広がりすぎる | hacomono等のAPI接続後に想定外のデータが取得される | API連携はPoC中は設定不可。取得項目を明示的に制限 |
| 設定画面で本番連携を誤操作する | PoC担当者が誤って本番APIキーを設定する | PoC中はAPI連携設定UIを非表示または読み取り専用にする |
| 高リスク機能の権限設計不足 | 顧客チャット・FC精算・採用など将来機能の権限が未定義 | 機能追加時に必ず権限設計を先行して実施する |

| 権限変更時の承認フロー | ロール変更は本部承認の上で実施するフローを定める |
| 退職・異動時のアカウント停止フロー | アカウント削除・ロール変更の手順とタイミングを定める |

| フィードバック | 対応方針 |
