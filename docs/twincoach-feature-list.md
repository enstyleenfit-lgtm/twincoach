# TwinCoach 機能一覧

> バージョン：2026-06-06  
> 対象：林さん提案・本部共有・PoC準備・設計資料作成

---

## 結論

- TwinCoachは、**本部・オーナー・店舗をつなぐジム運営OS**である
- 機能は「**退会予防**」「**LTV改善**」「**現場行動**」「**業務効率化**」の4軸で整理できる
- **PoCでは全機能を使わず、低リスクで価値検証できる機能を優先する**
- 本導入前に、機能ごとの**CRUD・権限・データ項目を詳細化**する必要がある

---

## 機能カテゴリ分類

| カテゴリ | 対象ロール | 概要 |
|---|---|---|
| A. 本部向け機能 | 本部 | 全店舗の横断把握・戦略判断・データ取込 |
| B. オーナー向け機能 | オーナー | 管轄店舗の合算管理・リスク確認・現場支援 |
| C. 店舗/トレーナー向け機能 | 店舗・トレーナー | 会員対応・セッション記録・タスク管理 |
| D. 共通機能 | 全ロール | 認証・ナビ・通知・設定 |
| E. PoC/連携準備機能 | 本部・PoC担当 | CSV取込・hacomono想定連携準備 |
| F. 将来構想機能 | 全体 | API本番連携・精算・採用・チャット等 |

## 機能ごとのリスク分類

リスクは「**業務への影響度**」「**データ変更の取り消しやすさ**」「**外部連携の複雑さ**」で判定する。

### 低リスク（表示・確認・補助機能）

表示のみ・読み取り専用・既存業務に触れない機能。

| 機能名 | カテゴリ |
|---|---|
| HQダッシュボード | A |
| オーナーダッシュボード | B |
| 全店舗LTV管理 | A |
| 高リスク会員確認 | B |
| 会員詳細（閲覧） | C |
| 会員一覧 | C |
| 介入タスク（閲覧） | C |
| お知らせ | D |
| 設定 | D |
| PoC運用説明 | E |

### 中リスク（入力・編集・CSV取込）

データを変更する操作。取り消し・修正は可能だが注意が必要。

| 機能名 | カテゴリ | 注意点 |
|---|---|---|
| セッション入力 | C | 誤入力に注意。履歴への影響あり |
| 履歴から作成 | C | 元データの変更なし。複製のみ |
| 介入タスク（作成・更新） | C | タスク起票・ステータス変更 |
| 会話メモ記録 | C | テキスト入力。削除ルール要確認 |
| CSVインポート | E | 取込後データ修正が必要な場合あり |
| インポート履歴管理 | E | ログ記録のみ |

### 高リスク（本番API連携・精算・顧客連絡・既存業務置換）

外部システム連携・金銭処理・顧客への直接コンタクトを含む機能。**PoC後、設計・契約・セキュリティを整理してから検討する。**

| 機能名 | カテゴリ | リスク要因 |
|---|---|---|
| hacomono API本番連携 | F | API認証・データ整合性・障害時影響 |
| FC精算機能 | F | 金銭処理・精算ロジック・契約との整合 |
| 精算書PDF発行 | F | FC精算と連動。法的効力の確認必要 |
| 精算書メール送信 | F | 送信ミスによるトラブルリスク |
| 顧客チャット/連絡機能 | F | 個人情報・誤送信・法務対応が必要 |
| kintone完全代替 | F | 既存業務停止リスク。段階移行が必須 |
| 契約/請求管理 | F | 法務・経理・セキュリティ整備が必要 |
